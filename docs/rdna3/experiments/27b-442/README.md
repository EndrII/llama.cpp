# Qwen3.8-27B tuning results

The local 9B-tuned build at commit 5b11a3613 was tuned for Qwen3.8-27B on the RX 7900 XT using the ROCm 10.1 SDK. The model GGUF is unchanged. No MTP or speculative decoding was used. Changes are applied, uncommitted, in /mnt/9100pro/ossicle-work/llama.cpp-decode-fold.

## Result

Final matched baseline/candidate run: median after dropping the first repetition; four repetitions, batch 2048, microbatch 512, F16 KV, empty context, 12 CPU threads, full layer offload. Longer interleaved decode runs independently confirmed about a 6.2% gain.

| Workload | Original | Tuned | Change |
|---|---:|---:|---:|
| Decode tg128 | 41.72 tok/s | 44.17 tok/s | +5.85% |
| Fast pp512 | 1995.70 tok/s | 2011.76 tok/s | +0.80% |
| Fast pp2048 | 1915.75 tok/s | 1934.43 tok/s | +0.97% |
| Quality pp512 | 1201.18 tok/s | 1218.43 tok/s | +1.44% |
| Quality pp2048 | 1103.41 tok/s | 1118.38 tok/s | +1.36% |

Quality rows were measured in the same session, separately from the final fast-preset matched pair. Small prefill differences are comparable to normal clock/thermal variation; the repeated decode gain is substantially larger.

| Matched whole-GPU peak VRAM | Original | Tuned |
|---|---:|---:|
| 20 ms sampling | 15.357 GiB | 15.474 GiB |

The matched sampled peak increased by 120 MiB. Both fit the 20 GB card. Earlier absolute peaks varied by configuration and allocation state; the matched pair above is the relevant comparison. These are whole-GPU measurements, not a precise allocator trace.

## Kept changes

1. Enable the existing GDN gate fusions for 48 heads. The matcher and skinny-projection paths previously capped at 32. Decode folds the alpha/beta projections and gates into GDN; prefill uses a three-panel BF16 WMMA kernel with a two-step load unroll.
2. Use 64 output rows per matvec block for the 27B output projections (four 16-row tiles). They share one fused norm/gate/rotation across the row tiles. Dispatch is restricted to M=5120 and K=6144 or 17408; other model shapes retain their original path.
3. Preserve the existing prefill GEMM layout. Other wave counts, tiles and unrolls were slower or indistinguishable.

## Accuracy

Prefill: same 24 WikiText test chunks, context 512, against the existing BF16 reference logits.

| Preset | Original PPL | Tuned PPL | Original KLD | Tuned KLD |
|---|---:|---:|---:|
| Quality | 5.958726 | 5.958872 | 0.018401 | 0.018352 |
| Fast | 6.206520 | 6.152013 | 0.062275 | 0.056538 |

The quality PPL difference is +0.0025%. Fast KLD decreased about 9.2%, and fast PPL decreased about 0.88%, on this sample. This does not establish broader benchmark improvement. The prefill unroll reduction preserved every reported metric to the displayed precision.

Decode-path checks use a reference generated by the original build at batch 1 on two 512-token chunks (512 scored predictions).

| Build / batch | PPL | KLD to original b1 | Top-token agreement |
|---|---:|---:|---:|
| base, b1 | 5.744043 | 0.000000 | 100.000% |
| final, b1 | 5.746768 | 0.000215 | 100.000% |
| base, b8 | 5.742550 | 0.000204 | 99.608% |
| final, b8 | 5.744652 | 0.000201 | 99.804% |

The tuned single-token path has small numerical differences (mean KLD 0.000215); all 512 top-token predictions matched. Single-token PPL was +0.047% on this small sample. The batch-8 PPL difference was +0.037%. These are bounded numerical checks, not proof of identical generated text.

## Final profile

All selected decode and prefill kernels report zero scratch allocation. The 64-row matvec uses 184 VGPRs; the 48-head skinny WMMA kernel uses 224 VGPRs. An earlier prefill experiment spilled 36 bytes/thread at 256 VGPRs; that version was discarded.

## Run the tested build

```bash
/home/svt/tuning27b/run_27b.sh llama-bench -p 0 -n 128 -r 7
GGML_INT4_PREFILL=fast /home/svt/tuning27b/run_27b.sh llama-bench -p 512,2048 -n 0 -r 7
```

GGML_INT4_27B_ROWS=1 disables only the new output-row sharing. The 48-head gate support remains enabled. The launcher uses the existing model and ROCm SDK; its bundled binaries no longer depend on Claude scratch-directory symlinks.

## Discarded experiments

Decode rotation wave counts 4/6/8/12/16/17, activation prepacking, row-sharing variants, prefill wave counts 2/4/8, GEMM tiles (MI,NJ)=(1,2),(2,1),(1,1),(4,1), and load unrolls 1/4 were measured. Only the consistent row-sharing winner and 48-head support were retained. Four-wave and eight-wave prefill were close; the existing per-weight rule was preserved.
